前言

以下涉及取模的话 unsigned long long 自然溢出就够了，因为这个 hash 不像字符串 hash，它的重点在 hash 函数的构造，它不可能卡你模数，要卡也是卡函数。

因此涉及 hash 的，重要的都是 hash 函数。

简介

树哈希，顾名思义就是对一整棵树弄出一个哈希值。

这里有一个概念。如果一棵树将所有点的编号打乱重排，得到的树和另一个树相等，那么这两个数就是同构的。简而言之就是这两棵树长得一样。

有根树做法

我们可以思考怎么样构造 hash 的方式才合适。

令以 iii 为根节点的子树的 hash 值为 hih_ihi​，iii 的子节点构成的集合为 SiS_iSi​。

如果同构，这两个根的所有子树就应该长得一样，我们就应该对根的所有子树做同等类型的运算。例如将子树的 hih_ihi​ 加或乘起来。

最小表示法

当然可以用最小表示法做。

首先将树用 01\texttt{01}01 序列化，一颗树在 dfs\texttt{dfs}dfs 的时候进入一个点时在序列末尾加上一个 000，出去的时候加上一个 111。

这样树就可以变成一个长度为 2n2n2n 的 01\texttt{01}01 序列。

判断两颗有根树是否同构就是看这两个序列的最小表示法是否相同。

▶
证明

首先一个 2n2n2n 的序列对应的树是唯一的，因为从根节点出发，如果遍历到了 000，就从当前节点往下走一个，111 就往上走一个，树的结构显然确定了。

有些人（我）可能会问，如果你这个最小表示法的起点不是根节点怎么办？

这种情况实际上是不可能出现的。

因为最小表示的开头肯定是尽可能多的 000，对应的实际上是根节点到叶子节点的路径最长的那一段，因此最小表示法的起点肯定是根节点。

最小表示法

相对有根树，无根树的做法就相对繁琐一点。

我们可以暴力设定每个点为根，都跑一遍最小表示法，然后取最小表示法的最小值进行比较。

但是我们可以优化。

如果两个树同构，那么它们的点肯定是一一对应的，我们就可以找出它的重心，对重心求最小表示法进行比较就行了。

但是如果有两个重心的话，对这两个重心都求一遍最小表示法，取其最小值进行比较，这比暴力少了一个 O(n)\mathcal O(n)O(n)。

题目描述

树是一种很常见的数据结构。

我们把 NNN 个点，N−1N-1N−1 条边的连通无向图称为树。

若将某个点作为根，从根开始遍历，则其它的点都有一个前驱，这个树就成为有根树。

对于两个树 T1T_1T1​ 和 T2T_2T2​，如果能够把树 T1T_1T1​ 的所有点重新标号，使得树 T1T_1T1​ 和树 T2T_2T2​ 完全相同，那么这两个树是同构的。也就是说，它们具有相同的形态。

现在，给你 MMM 个无根树，请你把它们按同构关系分成若干个等价类。

输入格式

第一行，一个整数 MMM。

接下来 MMM 行，每行包含若干个整数，表示一个树。第一个整数 NNN表示点数。接下来 NNN 个整数，依次表示编号为 111 到 NNN 的每个点的父亲结点的编号。根节点父亲结点编号为 000。

输出格式

输出 MMM 行，每行一个整数，表示与每个树同构的树的最小编号。
