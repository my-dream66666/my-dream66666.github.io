题解：P9694 [GDCPC 2023] New but Nostalgic Problem

题目

题目描述

给定 nnn 个字符串 w1,w2,⋯ ,wnw_1, w_2, \cdots, w_nw1​,w2​,⋯,wn​，请选出恰好 kkk 个字符串，最小化字符串 vvv 的字典序，并输出这个最优的字符串 vvv。其中 vvv 满足以下条件：vvv 是被选出的字符串中，某两个编号不同的字符串的最长公共前缀。而且，vvv 是所有满足条件的字符串中，字典序最大的字符串。

更正式地，令 S\mathbb{S}S 表示一个大小为 kkk 的集合，集合中的元素均为从 111 到 nnn 的整数（含两端），且没有重复的元素。令 lcp(wi,wj)\text{lcp}(w_i, w_j)lcp(wi​,wj​) 表示字符串 wiw_iwi​ 和 wjw_jwj​ 的最长公共前缀，您需要找到一个集合 S\mathbb{S}S 以最小化下述字符串 vvv 的字典序，并输出这个最优的字符串 vvv。

v=max⁡i∈S,j∈S,i≠jlcp(wi,wj)v = \max\limits_{i \in \mathbb{S}, j \in \mathbb{S}, i \ne j} \text{lcp}(w_i, w_j)v=i∈S,j∈S,i=jmax​lcp(wi​,wj​)

上式中的 max⁡\maxmax 通过字典序比较两个字符串。

请回忆：

  • 称字符串 ppp 是字符串 sss 的前缀，若可以在 ppp 的末尾添加若干个字符（包括零个字符）将它变成 sss。特别地，空字符串是任意字符串的前缀。
  • 字符串 sss 和 ttt 的最长公共前缀是一个最长的字符串 ppp，满足 ppp 既是 sss 的前缀，又是 ttt 的前缀。例如，abcde 与abcef 的最长公共前缀为 abc，而 abcde 与 bcdef 的最长公共前缀为空字符串。
  • 称字符串 sss 的字典序小于字符串 ttt（s≠ts \ne ts=t），若
    • sss 是 ttt 的前缀，或
    • s∣p∣+1<t∣p∣+1s_{|p| + 1} < t_{|p| + 1}s∣p∣+1​<t∣p∣+1​，其中 ppp 为 sss 和 ttt 的最长公共前缀，∣p∣|p|∣p∣ 为 ppp 的长度，sis_isi​ 表示字符串 sss 的第 iii 个字符，tit_iti​ 表示字符串 ttt 的第 iii 个字符。
  • 特别地，空字符串是字典序最小的字符串。

输入格式

有多组测试数据。第一行输入一个整数 TTT 表示测试数据组数。对于每组测试数据：

第一行输入两个整数 nnn 和 kkk（2≤n≤1062\leq n\leq 10^62≤n≤106，2≤k≤n2\leq k\leq n2≤k≤n），表示字符串的总数和需要选择的字符串的数量。

对于接下来 nnn 行，第 iii 行输入一个由小写字母构成的字符串 wiw_iwi​（1≤∣wi∣≤1061\leq |w_i|\leq 10^61≤∣wi​∣≤106）。

保证所有数据中字符串长度之和不超过 10610^6106。

每组数据输出一行一个字符串表示答案。特别地，若答案为空字符串，输出 EMPTY\texttt{EMPTY}EMPTY。

题意说明

给定 nnn 个字符串 s1,s2…sns_1,s_2\dots s_ns1​,s2​…sn​，从中选取 kkk 个， 令 lcp⁡(si,sj)\operatorname{lcp}(s_i,s_j)lcp(si​,sj​) 为 si,sjs_i,s_jsi​,sj​ 的最长公共前缀。

在一次选取的 kkk 个字符串中，又定义 VVV 为所选的字符串集合，则有字符串 SSS 为：

S=max⁡i∈V,j∈V,i≠jlcp⁡(si,sj)S=\max_{i\in V,j\in V,i\neq j}\operatorname{lcp}(s_i,s_j) S=i∈V,j∈V,i=jmax​lcp(si​,sj​)

max⁡\maxmax 比较方法是按字典序比较。

最后要将 SSS 的字典序最小化。

▶
字典序

将两个字符串从头开始比较，如果有一个字符串小，那么这个字符串字典序就小，如果相等，那么就比较下一位。

如果比较到某一位超出了其中一个字符串的长度，那么那个短的字符串的字典序小（即空的字典序小）。

做法

题目就是要我们求最大值的最小值。

这题方法比较巧妙，套路地将题目转化成判定性问题。

从头开始枚举每一位字符是什么。

假设枚举到了第 iii 位，在这一位中需要选出 xxx 个字符串，我们的操作步骤是这样的：

  • a…z\texttt{a}\dots\texttt{z}a…z 遍历一遍，如果有字符串包含，那么 xxx 就减 111，到最后如果 x≤0x\leq0x≤0，就 return，这位的答案为空。

    因为我们可以在 a…z\texttt{a}\dots\texttt{z}a…z 有字符串的每个选一个，在这一位他们的公共前缀为空，因为空的字典序最小，那么答案就到此为止了，否则进行下一步操作。

  • a…z\texttt{a}\dots\texttt{z}a…z 遍历一遍，如果有 y(y≠0)y(y\neq 0)y(y=0) 个字符串包含，在原来的基础上 xxx 减去 y−1y-1y−1（因为先前减去了一个 111），如果此时 x≤0x\leq 0x≤0，就将 xxx 加上 yyy，记录这一位的字符，枚举下一位。

    因为例如我们枚举到了 e\texttt{e}e，那么 a…d\texttt{a}\dots\texttt{d}a…d 肯定都全部选，所以减去，然后到了 e\texttt{e}e 就够了，所以这意味这一位答案为 e\texttt{e}e。

    接下来就要看下一位在 e\texttt{e}e 的基础上怎么选了，而且在 e\texttt{e}e 的基础上要选的数量就是原来的 xxx 减去 a…d\texttt{a}\dots\texttt{d}a…d 全选的，再减去 f…z\texttt{f}\dots\texttt{z}f…z 有的话选一个的（第一步）。所以要加上 yyy。（实际写代码的时候可以简化一些，例如先判断，就可以少一些加减）

还有一个小细节，引用上面的例子，如果有字符串就是在第 iii 位，以 e\texttt{e}e 结尾，那么它肯定要选，但是在下一位我们没有考虑也没有办法考虑它的贡献，所以我们在 e\texttt{e}e 的时候就要减去它，因为必选它肯定是优的。

最后就做完了。
